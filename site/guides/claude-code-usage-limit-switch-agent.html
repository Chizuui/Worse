Claude Code hit its usage limit? Switch agent and keep working

A usage limit in the middle of a task usually means waiting hours for the reset, or starting over in another tool and explaining everything again. Worse Harness continues the same session on another agent instead, with the conversation intact.

What you can fail over to

  • Another Claude Code account. Harness keeps several Claude accounts as separate profiles.
  • Codex, Antigravity or Command Code, if you use them.
  • An API model through any OpenAI-compatible endpoint: DeepSeek, OpenRouter, OpenAI, Gemini, Groq, Mistral, Kimi, Qwen, or a local model in Ollama or LM Studio. Harness runs it as a full agent with file and shell tools.
  • Several API keys for one service. They are used in turn, and a key at its limit is skipped until it resets.

Set it up

  1. Download Worse Harness and set up at least two agents. For an API model open Settings → Agents → API providers → Add provider, pick a preset and paste the key; the endpoint and a model are filled in for you.
  2. In Settings → Agents, arrange the Fallback order. Every enabled agent joins it; turn an agent off to take it out.
  3. Work as usual. Each session uses the agent you picked.

What happens at the limit

Harness recognises the usage-limit error of each agent. When the session's agent hits it, Harness switches to the next ready agent in your fallback order and continues the turn. The transcript belongs to Harness, not to one vendor's CLI, so the next agent sees the same conversation. You can switch back to the first agent by hand once its limit resets.

Spend the limit more slowly

You can also make the expensive agent last longer by handing routine work to a cheaper one. The built-in harness-delegate MCP server lets Claude Code start a subagent on, for example, a DeepSeek model for boilerplate edits or tests, and get the result back automatically.
